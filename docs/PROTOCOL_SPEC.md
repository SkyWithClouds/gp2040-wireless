# GP2040-CE 外挂无线桥协议 v1.0

本规范定义固定绑定、单人桌面样机的行为。上行依次为 Hitbox → Pico → 发射端 NOLOGO（TX）→ 接收端 NOLOGO（RX）→ Windows；下行承载确认和玩家灯。各阶段实现及实板验收状态见[仓库主页](../README.md)。协议实现须同时满足下列状态规则及仓库的[编解码定义](../common/protocol.h)和[固定向量](../tests/protocol_test.c)。

## 1. 输入报告边界

Pico 使用 Hitbox 最终的 XInput 状态。每次值变化生成一个完整快照，保留原有按键位、扳机、摇杆数值和方向。相同报告无须再入队。同一报告内同时发生的变化必须在接收端同一份 USB 报告提交；相邻两份不同报告分别排队，包括按下后立即松开。SOCD、映射和快捷键均由原板处理。中立输入定义为按键、扳机和四个轴均为零。

## 2. 线格式与校验

SPI 全双工每方向每事务 **24 字节**。ESB 开启动态载荷，应用数据与应用 ACK Payload 均为 **24 字节**。下表区分线上的绝对偏移和记录内部下标。

| 绝对偏移 | 长度 | 编码 |
|---|---:|---|
| 0–7 | 8 | `session_id`，无符号小端；0 留给未建链消息 |
| 8 | 1 | 记录 `b0`，类型；高半字节为主版本 1 |
| 9–22 | 14 | 记录 `b1…b14`，随类型解释 |
| 23 | 1 | 记录 `b15`，CRC-8/SMBUS |

所有多字节数按小端逐字节编解码；禁止直接复制编译器结构体作线格式。CRC 宽度 8，`poly=0x07`、`init=0x00`、`refin=false`、`refout=false`、`xorout=0x00`。计算覆盖绝对偏移 **0–22**，含会话号。ASCII `123456789` 的检验值为 `0xF4`。

下例每组为一字节。两条向量的会话号均为 `0x0807060504030201`。第一条表示序号 65535、按键 `0x8101`、扳机 `0x66/0x99`、四轴 `−32768/32767/−1/0`；第二条为空轮询。

```text
INPUT  01 02 03 04 05 06 07 08  10 FF FF 01 81 66 99 00 80 FF 7F FF FF 00 00 A1
POLL   01 02 03 04 05 06 07 08  17 00 00 00 00 00 00 00 00 00 00 00 00 00 00 C4
```

保留字节和保留位发送时清零。接收时拒绝长度错误、CRC 错误、未知类型或版本、保留位非零及非法字段。即使编解码通过，应用还须检查方向、当前会话、窗口和状态。无效记录不得推进进度或刷新在线计时。无线硬件另启用 16 位 CRC；固定地址、会话号和 CRC 不提供身份认证。

## 3. 八类消息

下表中所有字段均以记录内部的 `b` 为下标，省略的字节为零。`INPUT`、`SYNC`、`STATUS` 的完整字段见随后两表。

| 类型 | 方向 | 字段和约束 |
|---|---|---|
| `0x10 INPUT` | Pico → RX | 非零活动会话，完整状态，按序提交 |
| `0x11 SYNC` | Pico → RX | 候选会话的完整当前状态；序号必须为 0 |
| `0x12 HELLO` | Pico → RX | 外层会话为 0；`b1–8` 为非零 64 位 `hello_nonce` |
| `0x13 OFFER` | RX → Pico | 外层为 RX 分配的非零候选会话号；`b1–8` 原样回显非零 `hello_nonce` |
| `0x14 STATUS` | RX → TX → Pico | 非零会话，含累计进度、有效位和灯状态 |
| `0x15 RESET` | 故障端 → 相邻端 | `b1` 为原因：1 重启，2 超时，3 队列溢出，4 Hitbox 拔出，5 USB 主机复位。已知旧会话时携带旧会话号 |
| `0x16 HEARTBEAT` | Pico → RX | 非零会话；`b1–4` 为递增 32 位心跳号，`b5` 为灯已应用有效标记（0/1），`b6–7` 为最近成功下发的 `led_gen` |
| `0x17 POLL` | Pico → TX 或 TX → RX | 非零会话；`b1–14` 全零。由各跳独立发起以取回预装应答 |

### INPUT / SYNC 记录

| 字节 | 字段 | 定义 |
|---|---|---|
| b1–2 | `seq` | 16 位无符号，小端。`SYNC(0)` 后第一份变化为 1；普通输入允许 65535 → 0 |
| b3–4 | `buttons` | 原板 16 位 `wButtons`，保留方向位 |
| b5、b6 | `LT`、`RT` | 左、右扳机，各 0–255 |
| b7–8、b9–10 | `LX`、`LY` | 左摇杆 X、Y，各 16 位有符号二补数 |
| b11–12、b13–14 | `RX`、`RY` | 右摇杆 X、Y，编码同上 |

### STATUS 记录与有效位

| 字节 | 字段 | 定义 |
|---|---|---|
| b1 | `flags` | bit0 = TX_ACCEPT_VALID，bit1 = RX_ACCEPT_VALID，bit2 = USB_DONE_VALID，bit3 = LED_VALID，bit4–7 为零 |
| b2–3 | `tx_accept` | TX 的 SPI 队列已接收的最高连续序号 |
| b4–5 | `rx_accept` | RX 的 USB 待发队列已接收的最高连续序号 |
| b6–7 | `usb_done` | RX 已收到成功 USB IN 完成回调的最高连续序号 |
| b8–9、b10 | `led_gen`、`led_mode` | 本会话灯命令版本和主机原始模式 |
| b11–14 | 保留 | 全零 |

进度值为零也可以有效，例如 `SYNC(0)` 已交付。必须先检查相应有效位。无线 ACK 中 TX_ACCEPT_VALID 为 0；TX 将本地 SPI 进度填入发给 Pico 的 MISO 快照，同时保留已获知的 RX 进度和灯态，重新计算 CRC。

## 4. 建链、重启与同步

| 当前状态 | 事件 | 动作与转移 |
|---|---|---|
| 未建链 | Pico 获得原板有效状态并发起握手 | 生成新的非零 nonce，发 `HELLO`；同一次握手重发沿用该 nonce |
| 等待 OFFER | RX 收到 `HELLO` | 用 nRF 硬件随机源分配非零会话号，回 `OFFER`。同一候选握手重复到达则回同一提议。新 HELLO 本身不清除活动会话 |
| 等待 SYNC | Pico 收到匹配本次 nonce 的 `OFFER` | 原子复制最新快照作 `SYNC(0)`；从复制点起排队后续变化。重发同一份 SYNC 时保持内容不变 |
| 等待同步交付 | RX 收到匹配候选会话的 `SYNC(0)` | 切换会话并舍弃旧队列；若旧输入可能仍按住，先完成中立报告，再提交同步快照。USB IN 成功完成后回有效的 `usb_done=0` |
| 活动 | Pico 收到本会话的同步交付确认 | 开放普通 `INPUT(1)`。同会话重复 SYNC 只回报进度；过期会话的输入、确认和复位均丢弃 |
| 恢复 | 有效 RESET 或本地故障 | 结束旧会话，按第 7 节清零。Pico 用新 nonce 握手，以当前状态重新同步 |

TX 重启后清空缓存，向 Pico 通知重启并等待新的 HELLO；RX 重启后重新建链，拒收旧 INPUT。未建链 RESET 允许用零会话表示未知旧会话，状态机须辨别来源；零会话不能作为清除任意活动会话的通配符。Windows 尚未就绪期间，Pico 仍跟踪当前快照；等待期间若队列已溢出，废弃候选会话，以新快照重建。握手请求和同步包均可重发，普通输入须等同步交付确认。

## 5. 硬件接口和传输

### Pico 与发射端的 SPI

Pico 用 **Pin 1/GP0 为 D+、Pin 2/GP1 为 D−** 运行 PIO-USB Host；原生 USB 口用于供电和调试。SPI0 由 Pico 提供时钟，GP18/19/16/17 分别连 NOLOGO 的 P0.20/17/22/24（SCK/MOSI/MISO/CS）。GP20 读取 P1.00 的 READY，两板共地。实物排针编号见[接线表](USER_GUIDE.md)。

1. SPI Mode 0，MSB first，首版 1 MHz；CS 低有效，一次片选只传一帧，24 字节占用 192 µs 时钟。READY 高有效，复位默认低。
2. TX 独占 nRF52840 硬件 SPIS，用 `nrfx_spis` 和 EasyDMA 准备驻留 Data RAM 的双组缓冲。预装 24 字节 MISO 快照；RX 缓冲设为 25 字节，以便发现超长事务。
3. 收到 `NRFX_SPIS_BUFFERS_SET_DONE` 且 CS 已释放，TX 才置 READY 高。Pico 看到 READY 后拉低 CS；TX 用 GPIOTE 检测 CS 下降沿，经 PPI 触发 GPIOTE 输出任务清 READY。分配事件通道时避开 ESB 使用的资源。
4. `NRFX_SPIS_XFER_DONE` 后检查 `rx_amount == 24`，再校验和入队；短帧或达到 25 字节的事务均丢弃。准备下一组 DMA 缓冲与 MISO 快照后重新置 READY。MISO 在片选前已装好，当前读回的状态至多确认此前的事务。

### 两块 NOLOGO 的无线链路

TX 为 ESB PTX，RX 为 ESB PRX，2 Mbps，单信道 `RF_CH=40`（2440 MHz），固定一对地址，双方配置一致。开启硬件 ACK，初发后每轮至多自动重传 2 次。失败则保留队首，由后续调度继续。PRX 预装 ACK Payload，PTX 通过下一次业务包或 POLL 取状态。硬件 `TX_SUCCESS` 只表示本次无线事务成功；只有带有效标记的应用 STATUS 才能推进对应累计确认。

## 6. 队列、调度和计时

Pico 总缓冲为 **32 条变化记录**，含已发未交付的数据；滑动窗口为 **8 条未 USB 交付记录**。TX、RX 各自至少能容纳整个窗口。

1. **逐跳接收。** Pico 得到 `tx_accept` 后可向 TX 放行下一条；TX 得到 `rx_accept` 后停止对已接收记录的无线重传。后续记录可以在前一条等 USB 主机轮询时沿链路推进。
2. **最终交付。** RX 在前一份 USB IN 传输完成后才提交下一份变化。Pico 只按有效 `usb_done` 永久释放对应记录。USB 完成表示传输已到主机，游戏采样时间另计。
3. **缺号、重复和窗口。** 有缺口时保持最高连续进度并优先补最早缺失项；重发同序号保留同一状态，不重复入队。进度用 16 位模差比较，只接受本会话已发送窗口内的前进值。旧确认不得回退进度。窗口满暂停发送新记录，Pico 仍可在总缓冲内保存新变化；总缓冲溢出时复位，禁止覆盖未交付的按下或松开。
4. **有积压时主动取状态。** Pico 对 SPI、TX 对 ESB 分别用单调时钟调度。从最近一次实际开始且能取回应答的事务计时，目标 **1 ms**，正常可调度时上限 **2 ms**。等待任一相关入队确认或 `usb_done` 时持续执行，包括 SYNC(0) 等交付期间。首条变化和必要的重传立即发；INPUT、重传或到期 HEARTBEAT 可以顺带读回确认，空闲才另发 POLL。无 ACK Payload 或旧进度均不解除等待。
5. **资源暂忙。** READY 低则等待，无线重试期间不叠加事务。超 2 ms 记录超期，在下一可用时机立即服务，不追发过期空轮询。即使 `rx_accept` 追平，只要 `usb_done` 落后，两段链路都继续拉取。全部确认后退出快轮询。
6. **空闲与长按。** 活动会话中 Pico 每 **10 ms** 生成新编号 HEARTBEAT，即使输入繁忙也应获得发送机会；仅心跳更新灯已应用版本，不生成 USB 输入。POLL 不占输入序号和窗口，也不维持输入在线。HELLO/OFFER 阶段按握手重发；POLL 仅用于非零会话。

## 7. 断联、停滞与恢复顺序

| 故障条件 | 处理 |
|---|---|
| RX 连续 **50 ms** 未收到本会话新输入或 Pico 的新编号心跳 | 中止会话、清零。POLL、重复心跳、旧输入和硬件 ACK 均不续期 |
| 有输入待交付且 **50 ms** 内 `usb_done` 未推进 | 判定交付停滞，即使心跳正常也恢复。无待交付输入时不启动这个计时器 |
| 总缓冲溢出、板重启或 USB 主机复位 | 立即结束旧会话，尽可能通知相邻端，清理队列与旧进度 |
| 拔出 Hitbox | Pico 立即将本地快照清零并通知复位。通知丢失由接收端超时兜底；重插后等第一份有效原板报告再同步 |

恢复期间停止提交旧队列。若 USB 已有报告在途，允许其完成；在 USB 可用的下一次传输优先提交中立报告，再提交新会话当前快照。中断期间已经结束的动作全部舍弃；仍按住的键会在同步快照中重新出现。50 ms 是故障判定时间，主机暂停轮询时，实际收到清零报告还要等待 USB 恢复。

## 8. Windows XInput 与玩家灯

RX 原生 USBD 由 nRF Connect SDK v2.9.2 所带 Zephyr v3.7.99-ncs2-2 USB device stack 管理。使用自定义 Xbox 360 风格 Vendor Class，控制接口 class/subclass/protocol 为 `FF/5D/01`，包含 `0x21` 手柄专用描述符。端点地址须与该描述符一致。

| 端点 | 类型 | 最大包长 | 轮询间隔 | 用途 |
|---|---|---:|---:|---|
| `0x81` | Interrupt IN | 32 B | 1 ms | 20 B XInput 输入报告；成功完成才推进 `usb_done` |
| `0x02` | Interrupt OUT | 32 B | 8 ms | 收主机玩家灯或震动命令，处理后重新接收 |

使用项目获准使用的 VID/PID。EP0 实现 Microsoft OS 1.0 字符串索引 `0xEE` 及对应厂商请求，在 `wIndex=0x0004` 的 Extended Compat ID 描述符中为控制接口声明 `XUSB10`，并处理枚举过程中所需控制请求。Windows 10/11 自动绑定系统 XInput 驱动及 `XInputGetState` 成功读取，以实板记录验收。[上游端点描述符](https://github.com/OpenStickCommunity/GP2040-CE/blob/0ae800d6270c62f5754651074853cc2c648075a9/headers/drivers/xinput/XInputDescriptors.h) · [兼容 ID 实例](https://github.com/OpenStickCommunity/GP2040-CE/blob/0ae800d6270c62f5754651074853cc2c648075a9/src/usbfunctionmanager.cpp)

1. RX 以 OUT 实收长度校验命令头及声明长度。有效玩家灯命令为 `01 03 mode`，原样保存 `mode`。每收到一条新的主机灯命令，更新本会话 16 位 `led_gen`；重复发送同一份无线 STATUS 不增加版本。震动命令忽略，继续接收 OUT。
2. `0x00` 为灭灯，`0x02…0x05` 对应 1P…4P 闪烁后点亮，`0x06…0x09` 对应相应象限常亮。将最新命令的 LED_VALID、`led_gen`、`led_mode` 置入 STATUS，依次通过 ESB ACK Payload 和 SPI MISO 回传。输入优先；多个灯命令积压时允许合并为最新灯态。
3. Pico 仅对当前会话有效、尚未成功应用的版本向 Hitbox 发 XInput OUT。原板 OUT 成功才记录“已应用”，失败可重试；同一版本正在传输或已经成功时不重复下发，避免闪烁被重启。下一份 HEARTBEAT 携带有效标志与已应用版本。
4. 新会话重建时清除旧版本确认。RX 已知当前主机灯态则重新发布；尚未收到灯命令则 LED_VALID 为零。链路验证终点是原板 OUT 成功，外观灯效取决于原板硬件与固件。
